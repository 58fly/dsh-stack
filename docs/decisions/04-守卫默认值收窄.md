# 04 — 守卫默认值收窄到宿主真实注册的工具

## 背景

上游 `st-loop.mjs` 的默认值抄了别的 harness 的工具名：

```js
mutationTools: ['str_replace_editor', 'apply_patch', 'multiedit', 'notebook_edit', 'write', 'edit'],
checkTools: ['bash', 'sh', 'shell', 'pwsh'],
```

实测本机宿主（dsh 0.2.1-rc.5）注册的文件工具只有 `read` / `write` / `edit` / `read_image`，shell 只有 `bash` / `pwsh`。

## 决定

```js
mutationTools: ['write', 'edit'],
checkTools: ['bash', 'pwsh'],
```

## 理由

1. **多余的项不是「未来的兼容」，是误导**。配置里写着 `apply_patch`，读者会以为这套守卫支持补丁式改动；实际永远不会匹配。命名列表的全部价值在于它准确描述当前行为。
2. **宿主不存在这些工具**，不是「可能以后有」——它们属于别的 harness 的命名体系，本宿主没有对应物。
3. **静默失效风险**：若将来宿主给工具改名，列表不会报错，只是永远匹配不上。因此 `scripts/verify-host-api.mjs` 会读宿主的工具注册表逐项比对，名字对不上直接 FAIL。

## 代价

宿主新增文件工具（例如 `apply_patch`）时，必须手动加进 `mutationTools`，否则「改完没验证」对那种改法不生效。这条写在维护者本地约定的守卫改动规则里，校验脚本会在工具集变化时给出提示。

## 验证

```bash
node scripts/verify-host-api.mjs
# PASS mutationTools 全是宿主真实注册的文件工具  write, edit
# PASS checkTools 全是宿主真实注册的 shell 工具  bash, pwsh
```
