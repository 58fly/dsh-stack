# 05 — 技能前缀 `ds-*` → `st-*`，预设 id → `dsh-stack`

## 背景

本包的 29 个技能正文逐字来自 [aicodeking/deepseek-stack](https://github.com/aicodeking/deepseek-stack)，最初连名字一起沿用，全部叫 `ds-*`。而 `TonyZiYuan/dsh-ds-stack-preset` 用的是同一份技能、同一套 `ds-*` 命名，预设 id 也同为 `ds-stack`。

后果是真实发生过的：两个 bundle 可以并存安装，装完后技能列表里出现两套一模一样的 `ds-tdd`、`ds-ship`，无法判断当前会话用的是哪一套；`/ds-help` 到底是哪个包的，只能去翻 `node_modules`。同时 `dsh-stack` 与 `dsh-ds-stack-preset` 在插件管理页也长得像。

## 决定

1. 29 个技能目录名、frontmatter `name:`、正文里指向别的技能的 `/ds-xxx` 手势，全部改成 `st-*`（共 34 处手势引用）。
2. 守卫文件 `preset/ds-loop.mjs` → `preset/st-loop.mjs`，导出名与 `SOURCE_KIND` 改为 `st-stack-loop`，打回文案前缀改为 `st-stack checkpoint`。
3. 预设 id 改为 `dsh-stack`，显示名改为 `dsh-stack模式`，`description` 里明确写「该模式为 DeepSeek Stack 模式」——保留来源说明，改掉可撞名的标识。

## 理由

- **可见性就是功能**。选择器、技能目录、守卫消息三处都直接展示名字；名字一样，用户就没有判断依据。
- **`st-` 不占别人的位置**。全机扫描确认 `st-` 前缀除一个无关的第三方域名列表外没有占用，且与 `ds-` 等长——29 条 catalog 描述总长仍是 6830 字符（≈1708 token），每轮重发的成本一分不涨。
- **预设 id 用 `dsh-stack` 而不是 `st-stack`**。id 是用户在多处配置里会看到、会抄的值；与包名完全一致时，「装的是哪个包」和「选的是哪个预设」不需要二次翻译。

## 不选的方案

- **只改预设 id 和显示名，技能保持 `ds-*`**：撞名问题只解决一半，技能列表仍然无法分辨。这是最初提出的 L1 方案，被否。
- **前缀用 `dsx-` 之类更长的区分**：更长意味着更贵，且 catalog 描述总长会涨。
- **直接改技能正文里的措辞**：会让技能与来源彻底分叉，失去「覆盖目录即可同步」的能力。本次只动标识，散文一字未改。

## 代价

1. **技能不再是逐字节镜像**。`LICENSE` 与 `NOTICE.md` 已同步改为「正文保留、标识改名」，并写明改名原因与三件改动。这条以前是「零改动」卖点，现在改为「零散文改动」。
2. **同步来源要多跑一步**。`rsync` 覆盖回来的目录是 `ds-*`，必须重跑改名，否则会退回撞名状态。命令写在维护者本地约定的「同步技能来源」一节，`scripts/verify-skills.mjs` 会在漏跑时拦下。
3. **本机已保存的预设选择会失效**。profile 里 `selectedDefault: ds-stack` 需要改成 `dsh-stack`，否则启动时找不到该预设、退回内置 `standard`。
4. **用户已记住的 `/ds-tdd` 等手势全部作废**，这是破坏性变更，因此按 minor 发版（0.2.0）而不是 patch。
