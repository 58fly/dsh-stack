# 01 — 接手上游并改名 dsh-stack

## 动机

上游 [TonyZiYuan/dsh-ds-stack-preset](https://github.com/TonyZiYuan/dsh-ds-stack-preset) 是一个可用的 bundle（单 commit `f86c4ab`），但只有三个源文件、一个测试、零文档：无开发者约定、无 `CHANGELOG`、无 tag、`package.json` 停在 `1.0.0` 且 `private: true`、CI 只跑 `test/ds-loop.test.mjs`。要长期自维护，缺的是可验证性与可追溯性。

## 做了什么

1. clone 上游到 `/Volumes/data/dsh-stack`（原为空目录），保留为 `upstream` remote；新建 `origin` = `58fly/dsh-stack`（见 [决策 01](../docs/decisions/01-独立仓库非 GitHub-fork.md)）。
2. 包名 `dsh-ds-stack-preset` → `dsh-stack`，内部目录 `ds-stack/` → `preset/`（见 [决策 02](../docs/decisions/02-目录改名为-preset.md)）。
3. 版本重起 `0.1.0`：这是自维护线，不是上游 `1.0.0` 的续版。
4. 去 `private: true`，补 `engines`（`node ^22.19.0 || >=24.0.0`、`dsh >=0.2.1-rc.5`）、`files` 白名单、`dsh.manifestVersion` / `dsh.bundle.patch`、`repository` / `homepage` / `bugs`。

## 验收

- [x] `cordis.patch.yml` 的 include 路径为 `./node_modules/dsh-stack/preset/agent.cordis.yml`
- [x] `npm pack --dry-run`：41 文件 / 53 KB，含 29 个技能目录
- [x] `node test/ds-loop.test.mjs` 全绿
- [x] `git remote -v` 显示 origin 与 upstream 各一条 fetch/push

## 遗留

`origin` 指向的 GitHub 仓库尚未创建，首次 push 需先建仓（见 [issues/05](../issues/05-建远端仓库与首推.md)）。
