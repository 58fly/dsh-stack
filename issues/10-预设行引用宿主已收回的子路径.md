# 10 — 配置页显示「加载失败」、会话选择器里选不到：一行引用宿主已收回的子路径

## 动机

0.3.1 装进真实 DSH 之后：

- 插件页的「会话插件」下拉里，本预设显示为 `dsh-stack 模式（加载失败）`，旁边红字一行 `tool-subagent-list-agents (@deepseek-ai/dsh-tool-subagent-…)`；
- 新建会话的选择器里根本没有这个选项；
- **宿主日志里一条相关记录都没有。**

用户能感知到的就是「装了但用不了」，而且没有任何可查的报错。

## 故障

`preset/agent.cordis.yml` 里这一行：

```yaml
- id: tool-subagent-list-agents
  name: '@deepseek-ai/dsh-tool-subagent-control/list-agents'
```

宿主 0.2.2-rc.1 的 `@deepseek-ai/dsh-tool-subagent-control/package.json`：

```json
"exports": {
  ".": { "types": "./lib/types/index.d.ts", "default": "./lib/index.js" },
  "./src/*": "./src/*",
  "./package.json": "./package.json",
  "./locale/*.json": "./locale/*.json"
}
```

没有 `./list-agents`。而该包的 `lib/index.js` 第 154 行：

```js
function apply(ctx) {
  registerListAgents(ctx);
  ...
```

`list_agents` 工具早已并进主入口。我们那行是照着更早版本的宿主写的，宿主收回了子路径，我们没跟上。

## 为什么会变成「整份预设作废」

`dsh-agent-preset-registry` 的加载路径是逐行 import：任意一行抛 `ERR_PACKAGE_PATH_NOT_EXPORTED`，整个预设被记为 `broken`。

- 配置页读到 `broken` → 显示「加载失败」；
- 会话创建走 `presets.resolve(presetId)` → 抛 `agent-preset/not-found`；
- 这两处都在宿主内，且**宿主不打印我们那一行的失败原因**。所以现场只有一行红字，没有栈。

## 本次做法

1. 删掉该行，原位留注释说明子路径为什么不能再写。能力不变 —— `list_agents` 由 `tool-subagent-control` 主入口注册。
2. 新增 `scripts/verify-lines.mjs`，逐行做两件事：
   - 说明符能否在当前宿主 resolve（真实宿主模式）或在快照里存在（无宿主模式）；
   - 该行导出的 `Config`（zod）是否接受我们给的 config 键。
3. 新增 `scripts/snapshot-host-surface.mjs` + `test/host-surface.json`：宿主 0.2.2-rc.1 的 960 个可解析说明符，48 KB。CI 不装宿主依赖树（本包零依赖），靠它做确定性判定。
4. 接进 `npm test` 与 `scripts/verify-release.mjs`（`prepublishOnly`）：**预设行加载不了就不许发版**。
5. `docs/验收清单.md` 新增「I. 预设行契约」，其中 I4 是只能人眼确认的那一条：装到真实 DSH 后打开配置页，无「加载失败」，选择器里能选到。

## 验收

```bash
node scripts/verify-lines.mjs     # 32 行，全部可解析
npm test                          # 全绿
```

先红后绿：把那行加回去，真实宿主模式报 `ERR_PACKAGE_PATH_NOT_EXPORTED`，快照模式报「快照里没有这个说明符」；删掉才绿。

## 教训

- **「能挂载」不等于「每一行都能加载」。** `verify-mount.mjs` 验的是补丁里两条相对路径落在哪，`verify-host-api.mjs` 验的是宿主还有没有那些能力 —— 两者全绿也测不出「某一行写了宿主已经撤掉的子路径」。三个校验针对的是三种不同的失效方式，缺一个就会漏。
- **宿主收回子路径是完全静默的。** 包还在、名字还对，只是 `exports` 少了一个键；引用方拿到的是 import 期的 `ERR_PACKAGE_PATH_NOT_EXPORTED`，而预设加载器把它吞成 `broken`。这类变化只能靠「拿当前宿主的 exports 逐行核」发现。
- **发版前的验证必须覆盖「装上之后长什么样」。** 仓库内 `npm test` 全绿、`npm pack` 内容正确，用户装上仍然是红的。凡是「宿主读我们的产物」这条链路，验证点必须落在宿主侧。
