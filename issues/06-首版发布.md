# 06 — 首版发布 0.1.0

## 动机

`0.1.0` 是自维护线的第一个版本。按 AGENTS.md 的铁律，Git 先行：commit → tag → push → CI 发布 → 三方自检。

## 前置

- [ ] [issues/05](05-建远端仓库与首推.md) 完成（main 已推、CI 绿）
- [ ] `package.json` version = `0.1.0`，`CHANGELOG.md` 有 `## [0.1.0] - 2026-11-03`
- [ ] `npm test` 全绿、`git status --short` 为空
- [ ] 仓库已配 secret `NPM_TOKEN`（npm Automation token，账号 58fly）

## 步骤

```bash
# 1. 确认 npm 上还没有同名包被占（`dsh-stack` 若已被他人发布，需改名或走 scope）
npm view dsh-stack version    # 期望 E404

# 2. 打 tag 并推
git tag v0.1.0
git push origin v0.1.0

# 3. 等 CI
gh run watch --repo 58fly/dsh-stack

# 4. 发布后三方自检
npm run verify:release -- --verify
```

## 验收

- [ ] `npm view dsh-stack version` → `0.1.0`
- [ ] `npm view dsh-stack dist.tarball` 可下载，解包后 `preset/skills/` 为 29 个目录
- [ ] `git tag -l v0.1.0` 与 `git rev-parse v0.1.0` 在 origin 上也存在
- [ ] `npm run verify:release -- --verify` 通过
- [ ] 全新机器 `npm i dsh-stack` 后，profile 加上 bundle，新建会话能看到「DeepSeek Stack 模式」

## 风险

`dsh-stack` 这个包名在 npm 上可能已被占用。检查到 E404 之外的响应时，两条路：

- 改用 scope：`@58fly/dsh-stack`（同步改 `cordis.patch.yml` 的 include 路径与 `verify-manifest.mjs` 的期望值）
- 换名：如 `dsh-deepseek-stack`

任一都会影响 include 路径这条硬耦合，必须重跑 `npm test`。
