# 05 — 建远端仓库与首推

## 动机

`origin` 已配成 `https://github.com/58fly/dsh-stack.git`，但仓库尚不存在（`gh repo view 58fly/dsh-stack` → Could not resolve）。不建仓则无 tag、无 CI、npm 发布也无处追溯，铁律无法成立。

## 前置检查（全部已实测通过）

```bash
cd /Volumes/data/dsh-stack
npm test                 # 6 组全绿
git status --short       # 见下
gh auth status           # 已登录 58fly，scopes 含 repo / workflow
```

工作区当前是一批待提交改动（改名 + 新增脚本/文档 + 守卫加固），一次性作为首个提交。

## 步骤

```bash
# 1. 建 public 仓库，不初始化 README（本地已有）
gh repo create 58fly/dsh-stack \
  --public \
  --description "DeepSeek Stack 模式 agent 预设（DSH bundle）：29 个 ds-* 循环技能 + 常驻人格 + 轮次收尾守卫" \
  --homepage "https://github.com/58fly/dsh-stack#readme"

# 2. 补 topics（npm 源安装的插件页靠这些做检索）
gh repo edit 58fly/dsh-stack \
  --add-topic dsh --add-topic dsh-plugin --add-topic deepseek-harness \
  --add-topic agent-preset --add-topic deepseek-stack

# 3. 首个提交（含改名与新增，用 rename 友好的一次提交）
git add -A
git commit -m "feat: 接手 dsh-ds-stack-preset，改名 dsh-stack 并补齐工程规范

- 包名 dsh-ds-stack-preset → dsh-stack，目录 ds-stack/ → preset/
- 守卫加固：打回只列未证明文件、工具名收窄到宿主真实注册、单轮上限 1→2 且第二次更硬
- 新增四组自检脚本与发布门禁
- 新增开发者约定 / CHANGELOG / 中英 README / docs / issues"

# 4. 推 main
git push -u origin main

# 5. 确认 CI 绿
gh run list --repo 58fly/dsh-stack --limit 3
```
