# 03 — 四组自检 + 发布门禁

## 动机

上游只有一个测试（`test/ds-loop.test.mjs`），覆盖守卫行为。但坏掉的方式不止行为：

- 改名漏了 include 路径 → 安装后预设列表里没有它，测试仍全绿。
- 技能目录名与 frontmatter `name` 不一致 → 技能可加载但目录里显示的名字错。
- `files` 白名单漏了 `preset/` → 本地测试全绿，装完什么都没。
- 宿主升级后 `agent.steer` 语义变了 → 守卫静默失效。

这四类都不产生失败信号。补的都是「不报错的坏法」。

## 做了什么

| 脚本 | 断言什么 | 不通过意味着 |
|---|---|---|
| `scripts/verify-preset.mjs` | 装配完整性：insert 行、include 路径 = 包名 + 目录、技能根走 baseUrl、元数据、catalog 上限容得下最长描述 | 装完挂载失败 |
| `scripts/verify-skills.mjs` | 技能合法性：frontmatter 齐全、目录名 == `name`、描述长度、`/ds-*` 无死链 | 技能列表里出现坏项 |
| `scripts/verify-manifest.mjs` | manifest + 真实 `npm pack --dry-run`：白名单、`engines`、`peerDependencies`、bundle 声明、技能数 | 发出去的包装不上 |
| `scripts/verify-host-api.mjs` | 宿主私有契约 6 项：`agent/turn-stopping` 的调用点、`agent` 注入、`steer` 语义、`snapshotEvents` 存在、两组工具名在注册表里 | 守卫静默失效 |
| `scripts/verify-release.mjs` | 工作区干净、tag 与版本对齐、CHANGELOG 有当前版本小节、tag 后进包内容未变 | 发布出不可追溯的版本 |

`package.json` 的 `test` 串起前四个；`prepublishOnly` 挂第五个。

## 验收


实测：`17 checks passed` / `12 checks passed` / 四组脚本全绿；`verify-host-api` 6 项 PASS。

## 遗留

`verify-host-api.mjs` 在没装 DSH 的机器上（CI）打印 SKIP 并退出 0——判据本身依赖本机安装目录，跳过不是失败。这一点写在脚本注释里。
