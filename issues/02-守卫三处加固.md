# 02 — 守卫三处加固

## 动机

上游 `preset/ds-loop.mjs`（当时在 `ds-stack/`）的三个问题，都是实测出来的，不是推测：

1. **文案指向已处理的文件**。`analyzeTurn()` 从 `0` 扫到 `lastMutation`，本轮「改 A → 检查 → 改 B」时会把 A 也列进打回文案。模型被要求去验证一个已经验证过的文件。
2. **工具名有两成是别家的**。默认值含 `str_replace_editor` / `apply_patch` / `multiedit` / `notebook_edit` / `sh` / `shell`。实测本机 `dsh-tool-fs` 只注册 `read` / `write` / `edit` / `read_image`，`dsh-tool-bash` 注册 `bash`，`dsh-tool-pwsh` 注册 `pwsh`。
3. **无视打回就再没机会**。`maxSteersPerTurn: 1`，模型第一次收到打回仍然结束轮次时，守卫彻底沉默——而这恰是最该再说一次的情形。

## 做了什么

| 问题 | 改动 |
|---|---|
| 1 | `mutatedFiles` 收集范围收窄为 `lastCheck + 1 .. lastMutation` |
| 2 | `DEFAULTS.mutationTools = ['write','edit']`、`checkTools = ['bash','pwsh']`（见 [决策 04](../docs/decisions/04-守卫默认值收窄.md)） |
| 3 | `maxSteersPerTurn: 2`；`evidenceText(files, attempt)` 在 `attempt > 1` 时给更硬的第二版文案；`claim()` 返回已用次数供调用处选择措辞 |

`preset/agent.cordis.yml` 的 `ds-loop` 行已同步（`maxSteersPerTurn: 2`）。
