# 07 — 修复 {{cwd}} 导致会话启动失败

## 动机

用户要求复盘会话 `session-19333a62-3c89-475e-9d9b-d2fbb3eed82d`（工作目录 `/Volumes/data/deepseek-stack`）里原版包暴露的问题，确认我们的版本有没有处理。

结论：**没处理，逐行继承。**

## 故障

原会话每次选「DeepSeek Stack 模式」后，轮次立刻结束：

```
turn/end reason.error:
  unknown prompt variable "{{cwd}}" in section "deployment:persona-suffix";
  registered variables: provider, model
```

`TonyZiYuan/dsh-ds-stack-preset` 的 `ds-stack/agent.cordis.yml:54`：

```yaml
suffix: Your working directory is {{cwd}}.
```

宿主的渲染路径没有降级：

- `@deepseek-ai/dsh-system-prompt/lib/index.js:158` `function interpolate(input, variables, kind)`
- 同文件 `:174` 抛出上面那段文案
- 全仓只有两处注册变量：`@deepseek-ai/dsh-agent-loop/lib/index.js:1607`（`provider`）、`:1608`（`model`）
- `@deepseek-ai/dsh-persona/lib/index.js:42-47` 把 `config.suffix ?? ""` 原样交给 `systemPrompt.section`，不做任何豁免
- 内置 standard 预设（`@deepseek-ai/dsh-web-app/presets/standard.patch.yml:11-14`）只有 `prefix: ""`，没有 suffix——上游那句是凭印象加的

后果：会话建得起来，但模型一步都跑不了，只能切回 standard。

## 修复

- 删掉 `preset/agent.cordis.yml` 的 `suffix:` 行。工作目录本来就在运行时上下文块里，这行既多余又致命。
- 人格注释块改写为直接记录原因、错误文案、变量注册位置——下次有人想「补一句工作目录说明」能先看见。
- `scripts/verify-host-api.mjs` 增加第 6 项：从 `dsh-agent-loop` 源码正则抓出 `systemPrompt.variable("…")`，比对预设里所有非注释行的 `{{…}}`。
- `test/preset.test.mjs` 增加第 13 条：同一断言的独立版本，白名单硬编码 `provider`/`model`。原因见下。

## 为什么写两遍

`verify-host-api.mjs` 找不到 DSH 安装时打印 SKIP 并 `exit 0`——它查的是宿主私有契约，没宿主就没法查，这是对的。但 **CI runner 上没有 DSH**，这条最关键的检查在 CI 里等于不存在。

纯 node 断言不依赖宿主，所以硬编码白名单。代价是宿主新增变量时要手动同步；收益是这条检查在每一台跑 `npm test` 的机器上都真实生效。

## 遗留

- **升级后必须重启 DSH**。主进程在安装 bundle 时就把 include 树读进内存，运行中不重读磁盘 YAML。0.1.0 期间手改 `node_modules` 里的文件「不生效」就是这个原因，不是文件没写对。
- npm 上的 0.1.0 不撤（unpublish 会破坏已安装用户的可追溯性），用 0.1.1 覆盖 `latest`。

### 顺带修掉的 lockfile 缺陷

profile 的 `pnpm-lock.yaml` 里 `dsh-purge-community@…-1.6.69.tgz` 这条记录**没有 `integrity` 字段**，pnpm 12.16.1 的供应链策略检查因此拒绝执行任何安装：

```
ERR_PNPM_MISSING_TARBALL_INTEGRITY
  × 1 lockfile entries failed verification:
    dsh-purge-community@…tgz has no "integrity" field
```

`pnpm add` / `pnpm update` 全部失败，连换版本号都做不了。修法：按 tarball 真实内容算出 `sha512-YiCUSBm+Hevq56E1Yu3VoRQ5p1blN6RjUrixQBJDeEZ7zc32N5vgl3QgqzhOpgv2pi2K/tiN/jFvyvwUK009Jg==` 补进 resolution，之后 `✓ Lockfile passes supply-chain policies (453 entries in 2.6s)`。

注意：中途用 `pnpm add --lockfile=false` 绕过一次，那次顺带把 `ds-harness-remote` 0.6.0→0.6.2、`dsh-wish-specializer` / `dsh-prompt-enhancer` 也各跳了一个 commit（这三个都是 `github:` 源、版本标识就是 commit SHA）。补完 integrity 后跑正常的 `pnpm install` 让 lockfile 与磁盘对齐，四个变化都落在了 lockfile 里，不是静默漂移。

**升级后必须重启 DSH**：主进程在安装 bundle 时就把 include 树读进内存，运行中不重读磁盘 YAML。本次改动要重启才生效。
